# Loading application secrets (post-deploy)

The CDK stack provisions an **empty** Secrets Manager secret ("app secret"). Its
keys are wired into the ECS web/worker/migrate task definitions by
`infra/lib/compute.ts` → `buildSecretEnv`. Until you populate the secret with a
value for every key, the containers cannot start (ECS fails to resolve the
secret references).

Fill in `docs/secrets-template.json` with real values, then push it as the
secret's value in a single `put-secret-value` call.

## 1. Get the AppSecretArn from the stack outputs

The stack exports the secret ARN as the `AppSecretArn` CloudFormation output:

```bash
# Replace ShezminMarketplaceStack with your actual stack name (see `cdk list`).
AppSecretArn=$(aws cloudformation describe-stacks \
  --stack-name ShezminMarketplaceStack \
  --query "Stacks[0].Outputs[?OutputKey=='AppSecretArn'].OutputValue" \
  --output text)

echo "$AppSecretArn"
```

## 2. Load the filled-in template

From the repo root (so the `file://` path resolves), after editing
`docs/secrets-template.json`:

```bash
aws secretsmanager put-secret-value \
  --secret-id "$AppSecretArn" \
  --secret-string file://docs/secrets-template.json
```

> `put-secret-value` replaces the **entire** secret string with the JSON you
> supply, so the file must contain every key at once. Re-running it with an
> edited file rotates the values (creates a new version).

## 3. Build REDIS_URL from the Redis endpoint + AUTH token

`REDIS_URL` is **not** a value you get from a provider — assemble it from two
CDK-managed pieces:

- **RedisPrimaryEndpoint** — the `RedisPrimaryEndpoint` stack output.
- **Redis AUTH token** — auto-generated by CDK (`data.ts` → `RedisAuth`
  secret, a 64-char punctuation-free password). It lives in its own
  Secrets Manager secret.

```bash
# Primary endpoint from stack outputs
REDIS_ENDPOINT=$(aws cloudformation describe-stacks \
  --stack-name ShezminMarketplaceStack \
  --query "Stacks[0].Outputs[?OutputKey=='RedisPrimaryEndpoint'].OutputValue" \
  --output text)

# The RedisAuth secret has a CDK-generated name containing "RedisAuth".
# Find its ARN, then read the generated password:
REDIS_AUTH_ARN=$(aws secretsmanager list-secrets \
  --query "SecretList[?contains(Name,'RedisAuth')].ARN | [0]" \
  --output text)

REDIS_AUTH=$(aws secretsmanager get-secret-value \
  --secret-id "$REDIS_AUTH_ARN" \
  --query SecretString --output text)

# TLS is enabled on the cluster (transitEncryptionEnabled: true), so use rediss://
echo "rediss://:${REDIS_AUTH}@${REDIS_ENDPOINT}:6379"
```

Paste the resulting `rediss://:<AUTH>@<primaryEndpoint>:6379` string into the
`REDIS_URL` field of `docs/secrets-template.json` before running step 2.

## Keys the stack reads

Sourced from `buildSecretEnv` in `infra/lib/compute.ts` (`appKeys` array plus
`DATABASE_URL`, `DIRECT_URL`, `REDIS_URL`):

`AUTH_SECRET`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`,
`NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`, `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`,
`RAZORPAY_WEBHOOK_SECRET`, `RAZORPAY_ACCOUNT_NUMBER`, `TWILIO_ACCOUNT_SID`,
`TWILIO_AUTH_TOKEN`, `TWILIO_VERIFY_SERVICE_SID`, `SIGNZY_BASE_URL`,
`SIGNZY_USERNAME`, `SIGNZY_PASSWORD`, `SIGNZY_REALM`, `SIGNZY_LOGIN_PATH`,
`SIGNZY_PAN_PATH`, `SIGNZY_GSTIN_PATH`, `SHIPROCKET_EMAIL`, `SHIPROCKET_PASSWORD`,
`SHIPROCKET_WEBHOOK_SECRET`, `ANTHROPIC_API_KEY`, `RESEND_API_KEY`, `EMAIL_FROM`,
`S3_PUBLIC_BASE_URL`, `SENTRY_DSN`, `DATABASE_URL`, `DIRECT_URL`, `REDIS_URL`.

Every key in `docs/secrets-template.json` must be present in the loaded secret —
ECS `fromSecretsManager` fails the task if an injected key is missing. The set
above is exactly the template's keys; keep them in sync with `compute.ts`.

## Notes

- **S3 media uses the ECS task role on AWS** — there are no `S3_ACCESS_KEY_ID` /
  `S3_SECRET_ACCESS_KEY` keys. The task role has S3 read/write + KMS on the bucket.
  `S3_REGION` / `S3_BUCKET` are set as plain task env by the CDK. (Only set the S3
  key pair — and add them back to `compute.ts` — if you point at an external R2/MinIO
  bucket via `S3_ENDPOINT`.)
- **`S3_PUBLIC_BASE_URL`** is a placeholder until the CloudFront edge is deployed.
  The media bucket is private + KMS-encrypted, so uploaded images only serve
  publicly once CloudFront (with the custom domain) fronts it. Keep the placeholder
  URL so tasks start; media display comes online with the edge step.
- **Signzy paths** (`SIGNZY_LOGIN_PATH` / `PAN_PATH` / `GSTIN_PATH`) ship with the
  documented defaults in the template — confirm them against your real Signzy
  account and override if they differ. URL fields (`SIGNZY_BASE_URL`, etc.) must be
  valid URLs or the task fails env validation; use a valid placeholder if a provider
  isn't live yet.
- Do **not** commit the filled-in template — keep real values out of git
  (`docs/secrets-template.json` should hold placeholders only).
- After loading, force a new ECS deployment (or run the migrate task) so tasks
  pick up the now-populated secret.
